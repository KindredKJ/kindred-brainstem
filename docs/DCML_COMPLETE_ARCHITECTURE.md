# Complete DCML learning-loop architecture

BRAINSTEM is the cognitive model. DCML is native inside BRAINSTEM. The loopback runtime serves BRAINSTEM and delegates typed calls; attached models remain subordinate instruments.

The implemented local loop is: typed experience → evidence verification → deterministic outcome evaluation → non-uniform credit assignment → signed founder learning approval → immutable dataset → numerical policy optimization → candidate checkpoint → held-out canary → signed promotion → changed policy selection → benchmark/replay/consolidation or signed rollback. Foundation-model and adapter weights remain `NOT_TRAINED`.

SQLite migration 2 adds append-only, hash-addressed records for verification, rich experiences, evaluations, credit, datasets, replay, curriculum, concepts, causal and counterfactual records, performance, calibration, metacognition, policy parameters, training, canaries, benchmarks, regressions, signed approvals, lineage, consolidation, and missions without altering v1 records.
